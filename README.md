# ProjectPilot AI 🚀

> **AI-powered SDLC & Agile Planning Assistant.**
> Turn a one-line product idea into a complete, structured engineering plan:
> requirements, SDLC phases, sprints, user stories, risks, testing checklist
> and a recommended tech stack — generated by an agentic AI workflow.

ProjectPilot AI is **not a chatbot**. It is a structured AI workflow platform
that demonstrates Agile, SDLC, prompt engineering, generative AI and modern
full-stack development.

---

## ✨ Features

- **Agentic workflow** — 10 explicit planning steps run end-to-end on every idea.
- **Structured AI output** — strict JSON schema, deterministic parsing, no hallucinated free-form text.
- **Full SDLC plan** — 6 phases with objectives, tasks and deliverables.
- **Agile sprint planner** — multi-sprint plan with goals, durations and tasks.
- **User stories** — generated in proper "As a / I want / so that" format.
- **Risk analysis** — technical, security, scalability and timeline risks with mitigations.
- **QA checklist** — functional, UI, API, security and performance tests.
- **Tech stack recommendation** — frontend / backend / database / hosting / APIs with reasoning.
- **Timeline & milestones** — with a visual roadmap.
- **Modern SaaS UI** — dark, glassy, responsive, futuristic.
- **Persistence** — every plan is stored in SQLite and accessible from a dashboard.
- **Offline fallback** — works even without an OpenAI key (deterministic planner) so the demo never breaks.

## 🗄️ Database schema

A single `projects` table — the AI plan itself is stored as JSON for flexibility.

| column      | type      | notes                                     |
|-------------|-----------|-------------------------------------------|
| id          | INTEGER   | primary key                               |
| title       | VARCHAR   | short project title                       |
| idea        | TEXT      | raw user input                            |
| status      | VARCHAR   | `completed` / `failed`                    |
| plan        | JSON      | full structured plan (see schema below)   |
| created_at  | DATETIME  | UTC timestamp                             |

### AI plan JSON schema (top-level keys)

`summary`, `features`, `functional_requirements`, `non_functional_requirements`,
`sdlc_plan`, `sprints`, `user_stories`, `risks`, `testing_checklist`,
`tech_stack`, `timeline`, `workflow`, `title`.

## 🔌 API endpoints

Base URL: `http://localhost:8000/api`

| Method | Path                  | Description                                  |
|--------|-----------------------|----------------------------------------------|
| GET    | `/health`             | Health check                                 |
| GET    | `/workflow-steps`     | List of agent workflow steps (for the UI)    |
| POST   | `/generate`           | Run the agent on an idea, persist & return   |
| GET    | `/projects`           | List recent projects                         |
| GET    | `/projects/{id}`      | Get a single project + full plan             |
| DELETE | `/projects/{id}`      | Delete a project                             |

Interactive docs: **http://localhost:8000/docs**

### Example request

```bash
curl -X POST http://localhost:8000/api/generate \
  -H "Content-Type: application/json" \
  -d '{"idea":"I want to build a food delivery app."}'
```

## 🧠 Agentic AI Workflow

For each idea, the agent executes these 10 steps and produces a single
structured plan:

1. Analyze project idea
2. Extract core modules & features
3. Generate functional requirements
4. Generate non-functional requirements
5. Build SDLC lifecycle plan
6. Build Agile sprint plan
7. Generate user stories
8. Identify project risks
9. Generate testing checklist
10. Recommend tech stack & timeline

The frontend visualises this as an animated, step-by-step agent indicator
while the backend works.

### Prompt engineering

- A strict **system prompt** sets the persona (senior architect + agile coach) and JSON-only output rule.
- A **master prompt** carries the full schema with example types so output is deterministic and parseable.
- `response_format={"type": "json_object"}` is requested from OpenAI to guarantee valid JSON.
- A robust extractor (`utils/parser.py`) safely recovers JSON even from fenced or noisy responses.

## 🚀 Getting started

### Prerequisites
- **Python** 3.10+
- **Node.js** 18+
- (Optional) An **OpenAI API key**

### 1. Backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
copy .env.example .env          # then edit and set OPENAI_API_KEY
uvicorn app.main:app --reload --port 8000
```

Backend runs on **http://localhost:8000** · interactive docs at **/docs**.

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend runs on **http://localhost:5173** and proxies `/api` to the backend.

> No OpenAI key? The app still works — it falls back to a deterministic
> offline planner so you can demo the full UI end-to-end.

## 🛡️ Implementation notes

- CORS is restricted to the configured frontend origin in `.env`.
- All inputs are validated with Pydantic (`min_length`, `max_length`).
- DB sessions are scoped per request via FastAPI dependency injection.
- AI failures degrade gracefully to the offline planner — the API never returns a half-written plan.
- The frontend uses `axios` with a generous timeout (long AI calls) and renders loading + error states everywhere.
